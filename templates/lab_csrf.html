Attacker Page (Simulation)
This page simulates a malicious website that secretly sends a request while you are logged in.

If the target site has no CSRF protection, the forged request will succeed.

Malicious action:
“Change victim’s email to attacker@example.com”
{% if mode == "secure" %}
Secure mode expects a CSRF token. The attacker page cannot generate a valid token.
{% endif %}
Why this works
{% if mode == "vuln" %}

The server accepts a state-changing request without verifying it came from a real user action. Because you're logged in, your browser includes your session automatically.

{% else %}

The server requires a CSRF token. Without a valid token, forged requests are blocked.

{% endif %}
How it’s fixed

Use CSRF tokens for all state-changing requests (POST/PUT/DELETE). The token must be tied to the user session and validated on the server.
